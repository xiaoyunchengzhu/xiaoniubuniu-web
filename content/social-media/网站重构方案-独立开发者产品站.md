# 小牛不牛 — 独立开发者产品站重构方案

> 基于 10 个成功独立开发者网站的深度分析和你的新方向（Mac App → 多平台产品矩阵）

---

### 10 个站共有的模式

**1. 产品第一位。博客是辅助。**

没有人把博客放在首页 Hero 区域。首页的核心内容是：我是谁 + 我做了什么产品。博客是 SEO 获取和信任建立的工具，不是主业展示。

**2. 每个产品一个独立页面。**

页面结构高度一致：大产品截图 → 一句话价值主张 → 功能介绍（短视频/GIF 优于长文） → 下载/购买按钮 → 用户评价/数据证明。

**3. "一个人做的"是卖点，不是短板。**

他们不在网站上写"团队"、"公司"——直接放自己的照片、写自己的名字。独立开发者的个人品牌 = 信任感。你的脸就是最好的 Logo。

**4. 极简设计，内容驱动。**

没有動画轮播，没有复杂的 CSS 动画。黑白底色 + 产品截图 + 文字。页面加载速度极快（大多数秒开）。信息密度高但阅读负担低。

**5. 多产品用统一格式管理。**

有多个 app 的开发者（Sindre Sorhus 40+、Bjango 6+），都用统一的卡片或网格展示。每个 app 的详情页结构一致，用户可以预期地浏览。

**6. 博客内容 = 长尾 SEO + 技术营销。**

Marco 的 Overcast 发布文章动辄 5000 字，讲 LUFS 音频归一化算法。这种文章给他带来了什么？1）开发者社区的大量转发 2）Google 上所有"podcast audio processing"相关搜索的排名 3）潜在用户因为"这人懂技术"而下单。

## 二、你的网站现在的问题（对照标杆后）

| 问题 | 现在的状态 | 标杆做法 |
|------|-----------|---------|
| **首页定位** | 「出海折腾日记」— 这是博客标题 | 产品价值主张 — 告诉访客你能帮他解决什么问题 |
| **产品展示** | 埋在 `/products` 里面，纯 PurePaste 一个 | 首页就有产品入口，PurePaste 应该有专属 landing page |
| **导航优先级** | 博客第 2 位，产品第 3 位 | 产品应该在博客前面 |
| **工具 vs 产品 混淆** | 工具箱（别人的工具）和产品（自己的产品）混在一起，概念不清 | 自己的产品是「Apps / Products」，别人的工具是「Uses / Stack」 |
| **服务页** | 放在导航栏，接单为主 | 接单服务是阶段性的东西，应该放在关于页或者独立页面，不是导航主角 |
| **缺少下载/购买 CTA** | PurePaste 有 GitHub 和 DMG 链接，但没有突出"下载" | 产品页应该有醒目的绿色「下载」按钮，放在第一屏 |
| **缺少平台分类** | 没有按 Mac/iOS/Web 分类 | 未来多平台时必须有分类入口 |

## 三、重构方案

### 3.1 新导航结构

```
🐂 小牛不牛

  Apps  ▼           Blog       About
  ├── All Apps
  ├── Mac           ← 你现在的重点
  ├── iOS            ← 未来
  ├── Web            ← 网站类产品
  └── Android        ← 未来
```

说明：
- **Apps 是第一导航位**，下拉分类。这告诉访客：这是一个产品驱动的独立开发者，不是博主。
- **Blog** 保留，但名字从"博客"改成英文 "Blog"（和国际化一致，也减少干扰）。
- **About** 保留，整合现在的服务信息。
- **工具箱和服务** 从导航栏去掉，放到 About 页或者 Blog 的侧边栏。

### 3.2 首页新设计

**第一屏（Hero）**：

```
照片（左）  |  我独立开发 Mac / iOS / Web 应用（大标题）
            |  目前一个人在村里做产品。先做 Mac App，后面扩展到 iOS 和更多平台。
            |  这是我的全部产品 →（按钮跳 Apps 页面）
```

**第二屏（产品展示区）**：

展示最新的 3-4 个产品（App），每个产品卡片包含：
- App 图标
- 名称
- 一句话价值主张
- 平台标签（macOS / iOS / Web）
- 状态标签（已上线 / 开发中）
- 「了解更多」链接

**第三屏（最新文章）**：

保持现有的最新 3 篇文章。这是 SEO 和信任建立的内容区。

**第四屏（About 简述 + CTA）**：

一句话介绍自己 → 「了解更多」跳 About 页面。

### 3.3 产品系统重构

**每个产品是一个 Markdown 文件**（当前已是），但需要增强：

```yaml
---
title: "PurePaste"
date: "2026-07-09"
status: "released"               # released | beta | development
platforms: ["macOS"]              # macOS, iOS, web, Android, Windows
type: "app"                       # app | web-service | tool
app_store_link: ""                # App Store 链接（未来）
download_link: "/downloads/PurePaste_2.0.dmg"
price: "Free / Open Source"       # "Free" | "$4.99" | "Freemium"
icon: "/images/products/purepaste/icon.png"
screenshots:
  - "/images/products/purepaste/demo.gif"
  - "/images/products/purepaste/url-detect.png"
tags: ["macOS", "剪贴板", "效率工具"]
description: "..."
---

正文：详细介绍
```

**产品详情页结构**（参考 Bjango 和 Radek 的模式）：

```
┌──────────────────────────────┐
│  App 图标 + 名称 + 标语      │  ← 第一屏
│  大截图 / GIF 演示           │
│  [下载 Mac 版] [App Store]   │
│  价格 / 免费                 │
├──────────────────────────────┤
│  功能介绍（3-5 个核心功能）   │  ← 功能展开
│  每个功能配 1 张截图         │
├──────────────────────────────┤
│  技术细节 / 隐私承诺         │  ← 信任建立
├──────────────────────────────┤
│  FAQ                         │  ← SEO 长尾
├──────────────────────────────┤
│  其他产品 / 相关文章          │  ← 交叉推广
└──────────────────────────────┘
```

### 3.4 新增：平台分类页

```
/apps              → 全部产品
/apps/mac          → 只展示 macOS 产品
/apps/ios          → 只展示 iOS 产品（未来）
/apps/web          → 只展示 Web 产品（未来）
```

每个分类页是独立的 SEO 落地页：
- Title: "macOS Apps by XiaoNiuBuNiu — Indie Developer"
- 描述：列出所有 Mac 产品
- 每个产品有卡片 → 点击进入详情

### 3.5 工具箱和服务怎么处理

**工具箱** (`/toolbox`)：
- 保留，但不放在主导航
- 在 Blog 侧边栏或 About 页底部放一个链接入口
- 或者重命名为 `/stack`（参考 indie dev 常用命名）

**服务** (`/services`)：
- 从导航栏移除
- 整合到 About 页的底部作为 "Work with me" 区
- 或者作为独立页面，但不占主导航位置
- 理由：当你有 5 个 App 产品后，接单就不是你的主要身份了。App 产品收入 > 接单收入时，接单变成可选项。不要让它占据和产品同等的导航位置。

### 3.6 SEO 策略调整

| 旧关键词 | 新关键词 |
|---------|---------|
| 独立开发、出海 | **Mac app developer, indie macOS apps** |
| 建站服务 | **macOS utility, SwiftUI app, clipboard manager** |
| 工具箱 | **best Mac apps 2026, macOS productivity tools** |

每发布一个 App，写一篇详细的发布博文：
- 为什么做这个 App
- 技术选型（SwiftUI？AppKit？）
- 遇到的坑
- 数据（下载量、收入）

这种文章 = 最好的 App 营销，也是最好的 SEO 内容。

## 四、重构优先级和时间线

### 第一阶段：本周（为 PurePaste 发布做准备）

**1. 改造产品系统**
- 产品 frontmatter 增加 `platforms`、`price`、`icon`、`app_store_link` 等字段
- 产品详情页按照新结构重构（对标 Bjango / Radek）

**2. 首页改造（最小化改动）**
- Hero 标题从「出海折腾日记」→「独立开发 Mac / iOS / Web 应用」
- 产品展示区提升到首页第二屏

**3. 导航栏调整**
- Apps 放到第一位
- 工具箱和服务从导航栏移除

### 第二阶段：下个月（多产品时）

**4. 平台分类页**
- `/apps/mac`、`/apps/ios` 等过滤页面

**5. Blog 侧边栏**
- 放工具箱入口、产品链接、Newsletter 订阅

### 第三阶段：有 3+ 个产品时

**6. 产品交叉推广**
- 每个产品页底部展示「我的其他产品」
- 统一的产品卡片组件

## 六、与当前的差异总结

| 项目 | 当前 | 重构后 |
|------|------|--------|
| 导航首位 | 首页（无差异） | **Apps**（产品优先） |
| 导航二位 | 博客 | Blog |
| 导航后位 | 产品、工具箱、服务、关于 | **About**（整合服务） |
| 首页 Hero | 出海折腾日记 | **独立开发 Mac / iOS 应用** |
| 产品管理 | content/products/ MD | 同上 + 增强 frontmatter |
| 工具箱 | 主导航 | About 页链接 |
| 服务 | 主导航，独立页 | 整合到 About |
| 产品详情 | 和博客详情共用模板 | **独立产品页模板**（截图大型、下载 CTA 突出） |

---

> 这个方案的核心原则：**网站的第一优先级是让访客看到你的产品并下载/购买，而不是找到你的博客文章。博客是手段，产品是目的。**
